EBS 12.2 apps tier clone

Build a new Oracle E-Business Suite 12.2 application tier on a fresh Oracle Linux 8 server, connected to a database that already exists, with the ebsclone kit. Every step checks its own result and stops with the reason if something is wrong. Allow about 90 minutes for a first build and 15 for the teardown.

Source apps hostTarget VMDatabase server

Every command has a Copy button. Tick a step when it is done; ticks stay in this browser only.

How the clone works

ServerRoleWhat the kit does there
Source apps hostAn existing apps tier at the same patch level as the databaseRead only: its apps files are copied. Optionally refreshes its clone stage (step 05).
Target VMA freshly installed Oracle Linux 8 serverInstalls the prerequisites, receives the apps files, builds and starts the new apps tier.
Database serverHolds the PDB the new tier will useTakes a restore point, registers the PDB with EBS, applies the safety gate.
Safe by design: the target VM is cut off from the source and production databases before any EBS tool runs, the copy is stopped from sending mail or calling out before it starts, and a restore point taken first lets the database be put back exactly as it was.

1. Passwords for this session

Type each one once. The steps then have buttons that copy the right one. Nothing is saved or sent anywhere: the values stay in this browser tab and are gone when you close or reload it.

2. Settings

Every step reads the same settings file on each server. Fill it in once here; the install commands below carry it to each server together with the kit. Orange fields still need a value. Like the passwords, nothing typed here is saved or sent.

Collect the settings from the servers

Not sure of a value? Run each command below in the root session on that server. They only read: they find the running database, its home, scan and listener, the source's apps base and owner, the VM's name and address and any Oracle inventory already on it, and print them as settings lines. Paste all three outputs into Fill from an existing settings file below and press Fill the form. The database command lists every container database on the server and its PDBs as numbered choices: type the number of the one you want.

  local t="$1"; shift; local n=$#
  [ "$n" -eq 1 ] && { echo 0; return; }
  local i=1; for x in "$@"; do echo "  $i) $x" >&2; i=$((i+1)); done

}

fi
RL=$(echo "$OUT" | sed -n 's/^RL //p' | tr -d ' ' | sed 's/.*HOST=\([^)]*\).*/\1/; s/:.*//')

The build, step by step

    
How every step behaves: it prints OK / WARN / FAIL lines and ends with Next: <step> or STOP: <reason>. On STOP, fix what it names and run the same step again; the parts already done are skipped. Long tools run detached, so a dropped connection does not stop them: run the step again and it reconnects to the running tool.


    

      
Step 00 · check the target VM
Target VM · root1 min

      
Why: a read-only check of the operating system, names, disk, memory and EBS packages. On a fresh VM the package checks fail: that is what step 10 fixes.

      
/u01/ebsclone/kit/00_check_vm.sh

      
Expect on a fresh VM
OK for release, names, disk and memory; FAIL for the EBS packages and limits.

    


    

      
Step 10 · operating system prerequisites
Target VM · root5 min

      
Why: installs what EBS 12.2 needs on Oracle Linux 8 the way Oracle documents it: the oracle-ebs-server-R12-preinstall package and its dependencies, the apps owner and its limits, the Oracle inventory, the host entry, the Motif library link, the web port in the firewall and time synchronisation. It ends by running step 00 again.

      
/u01/ebsclone/kit/10_os_prereqs.sh

      
Done when
The step 00 run at the end shows every line OK. The VM needs access to the Oracle Linux repositories, or an offline copy of the packages in the folder named in RPM_DIR.

    


    

      
Step 01 · check the database
Database server · root1 min

      
Why: a read-only check that the PDB exists, the recovery area has room for a restore point, and the EBS database tools are in place.

      
su - oracle -c /u01/ebsclone/kit/01_check_db.sh

      
Done when
all checks passed. A WARN that the restore point is not taken yet is expected.

    


    

      
Step 05 · refresh the source's clone stage (optional)
Source apps host · root5 min

      
Why: the clone is built from the source's clone stage, a snapshot made by adpreclone. Run this only if the source has been patched since its stage was made. It also makes the matching database tools (appsutil.zip) for step 25. Skip it when the stage is already current.

      
su - applmgr -c /u01/ebsclone/kit/05_source_preclone.sh

      
You'll be asked
APPS password, then WebLogic password.

      

      
Done when
source stage ready

    


    

      
Step 20 · prepare the PDB
Database server · root1 to 10 min

      
Why: takes a guaranteed restore point before the first change, so everything after it can be undone. It records how the PDB was found (open or closed, and its services) so the teardown puts it back exactly, patches the PDB to the database home's level if needed (datapatch), and holds pending concurrent requests so nothing copied runs by itself.

      
su - oracle -c /u01/ebsclone/kit/20_db_prepare.sh

      
You'll be asked
yes, confirming the database administrator has agreed.

      
Done when
restore point taken and PDB prepared

    


    

      
Step 25 · register the PDB with EBS
Database server · root8 to 30 min

      
Why: run it as root; it switches to oracle by itself after asking for the source's password. Oracle's txkPostPDBCreationTasks creates the EBS database service and network files and runs AutoConfig on the database tier. It restarts the container database, so any other PDB in it opens briefly; the step closes those again.

      
/u01/ebsclone/kit/25_db_register.sh

      
You'll be asked
First the source's root password (the prompt names the source: root@source's password), to pick up the database tools step 05 made. If step 05 was skipped, the step says so and carries on with the tools already on this server. Then APPS, then SYSTEM.

      

      
Done when
txk + AutoConfig completed, APPS can log in over the new service

    


    

      
Step 30 · copy the apps files
Target VM · root5 to 20 min

      
Why: run it as root; it switches to the apps owner by itself after asking for the source's password. It copies the apps code from the source without its configuration, adds the Oracle Linux 8 check files from patch 33471111, and reads the source's own configuration for every database, host and service it points at. The copy is pointed at the new database and this VM instead, and step 40 blocks the rest. It can run while step 25 is still running.

      
/u01/ebsclone/kit/30_stage_apps.sh

      
You'll be asked
The source's root password, once (the prompt names the source: root@source's password), to place a temporary copy key there. The key removes itself after the copy.

      

      
Done when
temporary copy key removed, move plan names nothing of the source's, staged

    


    

      
Step 40 · build the apps tier
Target VM · root30 to 40 min

      
Why: first cuts this VM off from every database, host and address the source's own configuration names (step 30 read them from it, so there is nothing to fill in), and keeps that block across reboots. Then Oracle's adcfgclone builds WebLogic, the web tier and the configuration from a prepared answers file, so it asks no questions. Last it removes the source's settings and checks that nothing still names the source.

      
/u01/ebsclone/kit/40_configure_apps.sh

      
You'll be asked
APPS password, WebLogic password.

      

      
Check along the way
The hosts blocked lines list what this VM can no longer reach. The key answers line must name PDB, DB_HOST and NEW_BASE. Progress then sits at 0% and 50% for 20 minutes or more; that is work, not a hang.

      
Done when
AutoConfig completed successfully, every JDBC URL names the new service, apps tier configured, not started

    


    

      
Step 50 · safety gate
Database server · root1 min

      
Why: the PDB is a copy of real data. Before anything starts, this removes network access rules, stops the workflow mailer, clears the mail relay setting and holds pending requests, so the copy cannot send mail or call out.

      
su - oracle -c /u01/ebsclone/kit/50_safety_gate.sh

      
You'll be asked
yes

      
Done when
no host ACEs left, mailer stopped and manual, smtp_out_server empty, no database links left, safety gate applied

Teardown

    
Puts everything back as it was found, so the build can be practised as often as needed. About 15 minutes.

Target VM · root5 min

      
Why: stops the new tier, waits until every one of its processes has exited, unregisters its Oracle homes, deletes its folder and removes the firewall block from step 40.

      
/u01/ebsclone/kit/95_reset_apps.sh

      
You'll be asked
yes, APPS password, WebLogic password.

What a hang looks like: the log has not grown for 20 minutes and its last line ends in a question. The step then stops the tool and says stalled waiting for input. A progress counter that sits at 0% or 50% while the log keeps growing is not a hang.

  


  

    
Known problems and fixes

    

      
What you seeCauseFix

      
Step 00: package and limit checks FAILA fresh VMRun step 10

      
Step 10: the preinstall package cannot be installedNo access to the Oracle Linux repositories (the package is in ol8_addons, which step 10 switches on for the install)Give the VM repository access, or put the package and its dependencies in the offline folder and rerun

      
Step 25: txk stops at Enter HostnameThe database listener lacks USE_SID_AS_SERVICE_LISTENER=ONAdd it to the listener.ora named in the settings, reload the listener, rerun step 25

      
Step 30: could not install the copy keyWrong root password for the sourceRerun step 30 and type it again

      
Step 30: stage check files do not know Oracle Linux 8Patch 33471111 is not on the VMDo "Put patch 33471111 on the target VM", rerun step 30

      
Step 40: source/PROD names leftA source name the answers file rewrite did not coverRead the listed lines and correct the settings, rerun step 40

      
Step 40: FMW_Home or inst left from an earlier attemptA previous adcfgclone attemptAnswer yes to remove them, or run step 95 with --keep-copy

      
Step 60: managers at 0, the log says giving upAnother apps tier's concurrent manager is still connected to this PDBStop that tier fully (its processes can take minutes to exit), then rerun step 60
